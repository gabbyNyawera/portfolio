# Grilling: Case Study Content Structure

**Blocked by:** (none — but logically follows visual refinements)
**Status:** ✅ Resolved

## Question

How should case studies visually present process documentation, visual showcase, and metrics/outcomes?

The current structure is Context → Role → Process → Outcome → Lessons. We need to add:
1. **Process documentation** — wireframes, user flows, research findings
2. **Visual showcase** — high-fidelity mockups, before/after comparisons
3. **Metrics/outcomes** — quantifiable impact

Key decisions:
- Where in the case study flow do these appear?
- How are they visually presented (full-width images? side-by-side? interactive?)
- What's the right level of detail for each section?
- How do we handle case studies that don't have real metrics?

## Resolution

All decisions locked:

### 1. Process Documentation Placement
**After Context/Role, before Outcome** — follows the natural narrative arc: problem → approach → result. The "Process" section should be visual, not just text.

### 2. Visual Showcase
**Full-width images** — maximum impact, immersive. Keep it simple. Device frames can be added later if needed, but full-width is the baseline.

### 3. Metrics/Outcomes
**Big number + context** — "40% increase in daily active users" with a brief explanation. Numbers need context to be meaningful.

### 4. No Metrics Case
**Be honest + use qualitative outcomes** — credibility matters. "This was a personal project" is better than fake metrics. Pair with qualitative feedback if available.

### Implementation Notes
- Case study sections should follow: Context → Role → Process (with visuals) → Outcome (with metrics) → Lessons
- Process sections should include full-width images (wireframes, flows, mockups)
- Outcome sections should lead with a big number, followed by context
- When no metrics exist, use qualitative outcomes and be transparent about the project type
